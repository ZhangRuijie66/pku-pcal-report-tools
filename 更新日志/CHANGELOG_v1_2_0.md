# v1.2.0

- **类型**：功能
- **日期**：2026-11-09
- **说明**：紫外光谱模块的标定从「写死三次」改为**可增删的标定清单 + 每条曲线可选标定**（默认设置与报告输出完全不变）

## 变更

### 一、标定条数可增减

原来标定清单 `uv.CALIBRATIONS` 是写死的三条，报告 `3.1` 节也用
`c1, c2, c3 = cals['d1_long'], cals['d2_long'], cals['d2_short']` 解包，
所以**根本没法多一条**——多做了标定也进不了报告。

- 新增 `uv.effective_calibrations()`：出厂三条（`CALIBRATIONS`，不变）+
  用户在界面上添加的（存 `settings.json` 的 `calibrations`）。
  同 `key` 时用户条目**覆盖**默认（可以把某条默认标定换成自己重测的光源谱）。
- 新增界面「＋ 添加一条标定」：填名称、简称、选光源谱文件
  （可搜索的文件选择器）、可选填先验 `a/b`；工具自动找特征峰拟合。
  不填先验也能用（走全局寻峰 + 候选组合拟合）。
- 新增界面「删除」：自定义条目可删；被删的标定若还被某条曲线选中，
  自动回落到该曲线的默认值。
- 新增 `GET /api/cals/options`：列出数据目录里可作为光源谱的 txt
  （标出已被哪条标定占用），只读、不写盘。

### 二、每条曲线可选标定

原来每条样品用哪条标定是 `SAMPLES` 里写死的 `cal='d2_long'` 字段，
界面上改不了。

- 新增 `uv.CURVE_CAL_DEFAULT`（出厂默认分配，与原写死值逐一相同）
  与 `uv.curve_cal_map()`：界面上的逐条选择存 `settings.json` 的 `curve_cal`，
  覆盖默认。
- 界面「标定结果」卡片下新增「每条曲线用哪条标定」：18 条曲线按
  「A3 浓度系列 / 各分子 / 光源对比」分组列出下拉框，改过的会标「非默认」，
  另有「全部恢复默认」按钮。
- 选了不存在（已删除）的标定时**退回该曲线的默认值**，绝不 KeyError。

### 三、报告 3.1 节按清单动态生成

- 子节编号 `3.1.1 ~ 3.1.N`、图号、「本实验中……使用该标定结果」全部跟着
  实际清单走，不再写死三条。
- 图号从 **图2** 起（图1 留给引言的预习笔记），自定义条目多了也不会撞号。
- 「三个特征峰」改为按实际参与拟合的谱线条数（`_n_peak_word`），
  没有先验、寻峰个数不同时不会印错。
- 自定义标定的「使用该标定结果」那句由 `_cal_note()` 按实际用到的曲线
  自动归纳（如「本实验中 A4、A3 的浓度系列使用该标定结果。」），不编造。

## 默认设置不变（重要）

用户明确要求「默认设置不变」，所以做了**逐字级**回归：

- 默认配置下 `effective_calibrations()` 返回的就是出厂三条，顺序不变。
- 默认曲线分配与原 `SAMPLES[*]['cal']` **逐条相同**（有测试钉住）。
- 用 `git archive HEAD` 还原改动前的代码到临时目录，同一份数据各生成一份
  docx 对比：**310 个段落逐字相同**（差异只在 zip 时间戳）。
  这一条比「测试全绿」更硬——它证明默认路径下的报告一个字都没变。

## 修复

- **`_analysis` 缓存键缺标定相关项**：改了标定或曲线标定后点「重新计算」
  会拿回缓存里的旧结果，界面显示「计算完成」但数字没动，属于静默不生效。
  缓存键现在包含 `calibrations`、`curve_cal`、`molecule_default`、
  `conc_pick`、`voigt_peaks`。
- `_coerce` 补列表分支：`calibrations` 走 `clean_calibrations` 清洗，
  非法 `key`（含空格/路径分隔符）不会进槽位名 `cal:<key>` 与图文件名
  `calib_<key>.png`。
- `/api/cals/options` 一开始误写在 `do_POST`，且用了 `do_GET` 里不存在的
  `u.path`（该作用域用的是 `path`/`q`），返回 404；已改正。
